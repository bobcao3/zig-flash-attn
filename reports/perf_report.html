Each point is the median time of one call that benchmarks/benchmark_attn.py or benchmarks/benchmark_inter_sequence.py measures with its default arguments, and reports/update_perf_report.py writes the records of the scripts into this page. The inputs are bf16 values drawn from N(0, 1), with a 2048 model dimension and 16384 tokens. The scripts time each implementation in CUDA graphs and change the order of the implementations from round to round. torch SDPA runs cuDNN where cuDNN accepts the case and PyTorch's FlashAttention otherwise; the legend names the backends, and the tooltip of a bar names its backend. FA4 is flash-attn-4 (CuTe) on SM90, SM100 and SM120 GPUs. On SM120 GPUs, Zig-SM120 is zigfa with its SM120 kernels and Zig-SM80 is zigfa with its SM80 kernels. A dash marks a case that an implementation does not run with its default settings.

The GB10 points come from an earlier version of these scripts, with the best of two runs, PyTorch SDPA's default backend and the FA4 of that time, and the current scripts have not measured them again. Its SM80 points also predate the L2 sections of the causal SM80 grids and the head dim 128 backward change.

Each inter-sequence point adds whole samples of one layout until they hold at least 16384 tokens. A sample holds these sequences:

  • captions: four texts and three 280-token images
  • image → text: one 560-token image and one text
  • text → image: one text and two 1024-token images
  • interleaved: two texts and three 1024-token images
  • 4096-token images: two texts and three 4096-token images

A text holds 32 to 511 tokens, or 64 to 511 beside 1024-token and 4096-token images. A sequence sees the earlier sequences of its sample that the layout names in full; an image sees itself in full and a text sees itself causally. A point runs 2048 / head dim query and key heads. FlexAttention runs as torch.compile(flex_attention) with a block mask of the same visibility and its default settings. FA4 runs with a CuTe mask_mod of the same visibility; on SM120 GPUs FA4 has no block sparsity, so it computes every block. TF/s count only visible query-key pairs.

Inter-sequence attention kernels

Inter-sequence attention packs many short sequences end to end on one token axis, and a visibility rule names the sequences whose keys each query sequence sees. Each figure below shows one technique of these kernels. On SM80-class GPUs, head dims 64 and 128 run in a persistent kernel and head dim 512 in a variant of it that splits the head dim across a warp pair; head dim 256 runs in the regular forward, which reads the same block table.
